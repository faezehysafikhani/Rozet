# حالت نمایشی (Local Storage)

این برنچ برای ارائه/دمو ساخته شده است: **هیچ درخواستی به بک‌اند (Nexus Core) ارسال نمی‌شود** و تمام داده‌ها از
`localStorage` مرورگر خوانده و در آن ذخیره می‌شود. کد صفحه‌ها (`App.jsx`) و hookها تغییر منطقی نکرده‌اند؛ فقط لایه‌ی
شبکه عوض شده است.

## اجرا

```bash
npm install
npm run dev        # http://localhost:2400
```

صفحه‌ی ورود با حساب `admin@nexus.local` و رمز `Demo@1234` پر می‌شود؛ زیر فرم هم دکمه‌های ورود سریع با
نقش‌های مختلف (مدیر سیستم، مدیر پروژه، مدیر مالی، مهندس اجرا) هست. رمز همه‌ی حساب‌ها `Demo@1234` است.

## چه چیزهایی داده‌ی نمونه دارد

| بخش | محتوا |
| --- | --- |
| کاربران و دسترسی | ۱۲ کاربر (یک غیرفعال، دو بدون سمت)، ۸ سمت سازمانی سلسله‌مراتبی، ۴ گروه، کاتالوگ دسترسی‌ها، چارت سازمانی |
| تاریخچه ورود | حدود ۲۰ رویداد ورود/ورود ناموفق/تغییر دسترسی (ورودهای جدید هم ثبت می‌شوند) |
| مدیریت پروژه | ۴ پروژه، ۱۵ وظیفه (کانبان/تقویم/تأخیر)، فعالیت‌های WBS، گزارش پیشرفت، مستندات، خروجی‌ها، KPI، ریسک، ذینفعان، اعضای تیم |
| چت | ۵ گفت‌وگو با پیام‌های قبلی؛ بعد از ارسال پیام، همکار مقابل **چند ثانیه بعد خودکار پاسخ می‌دهد** و اعلان زنده می‌رسد |
| اعلان‌ها | چند اعلان خوانده/نخوانده برای کاربرهای نمایشی |

تاریخ‌ها نسبت به «امروز» ساخته می‌شوند، پس تقویم و شمارنده‌ی تأخیر همیشه زنده است.
دسترسی‌ها مثل Core اعمال می‌شوند (مثلاً «مدیر مالی» نمی‌تواند کاربر بسازد و 403 می‌گیرد).

## ابزار ارائه‌دهنده

دکمه‌ی زرد «حالت نمایشی» بالای صفحه:

- **ارسال اعلان آزمایشی**: یک اعلان زنده به زنگ بالا می‌فرستد.
- **بازنشانی داده‌ها**: همه‌ی تغییرات را پاک و داده‌ی اولیه را برمی‌گرداند (قبل از جلسه توصیه می‌شود).

## ساختار کد

```
src/mock/seed.js            داده‌های اولیه (فارسی)
src/mock/db.js              خواندن/نوشتن در localStorage (کلید rozet_mock_db)
src/mock/mockServer.js      مسیریاب endpointها با همان قالب پاسخ Core
src/mock/mockHub.js         جایگزین SignalR (چت و اعلان زنده)
src/mock/MockModeBadge.jsx  دکمه‌ی ابزار + ورود سریع
```

سوییچ در `src/services/config.js` (`USE_MOCK`) است و در `api.js`، `authStore.js` و `signalr.js` استفاده می‌شود.
برای برگشت به بک‌اند واقعی: `VITE_USE_MOCK=false` در `.env`.

## محدودیت‌ها

- محتوای فایل‌های آپلودی ذخیره نمی‌شود، فقط نام و حجم (به‌خاطر سقف حجم localStorage).
- گفت‌وگوی گروهی در حالت نمایشی پشتیبانی نمی‌شود (UI فعلی هم فقط گفت‌وگوی مستقیم دارد).
- داده‌ها به مرورگر/پروفایل وابسته‌اند؛ در پنجره‌ی ناشناس با بستن پنجره پاک می‌شوند.
